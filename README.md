# CAN分布式采集与边缘网关系统 README

> 项目名称：CAN总线分布式采集与边缘网关系统
> 硬件：STM32F407ZET6（边缘网关） + STM32F103ZET6（采集节点）
> 开发环境：Keil‑MDK‑ARM5，STM32CubeMX，HAL库，FreeRTOS
> 固件版本：V1.0.0 Release

## 一、项目简介
本项目模拟工业分布式采集‑边缘网关架构，由**F103采集节点**与**F407网关**两部分组成。

- F103采集节点：完成NTC温度、电位器电压、按键IO信号采集，按照自定义CAN2.0B应用层协议组帧，附加CRC8校验，通过CAN总线上传数据。
- F407边缘网关：基于FreeRTOS实时操作系统，严格遵循`BSP`/`APP`分层架构；实现CAN报文解析、节点在线状态管理、故障管理器、系统任务心跳监控、独立看门狗IWDG保护；提供UART‑CLI串口维护交互接口，实现数据上报、故障记录、参数配置、命令交互。

系统具备完整容错能力：CAN Bus‑Off总线故障自动恢复、节点上下线检测、业务故障记录、任务卡死监控、参数掉电保存；区分业务故障与整机死机，避免总线空闲导致看门狗误复位。可通过串口上位机完成状态查看、参数修改、故障查询。

>分层设计说明
1. **BSP层**：封装寄存器/HAL硬件操作，提供统一接口，不包含业务逻辑；硬件改动只修改BSP。
2. **APP层**：业务逻辑、协议解析、状态机、故障处理，不直接操作寄存器，依赖BSP提供接口。

## 四、编译与烧录
1. 使用Keil‑MDK‑ARM5打开对应工程`.uvprojx`
2. `Rebuild all target files`全量编译，输出hex文件至`firmware_output`
3. 烧录：F407烧录网关固件，F103烧录采集节点固件
4. 硬件注意：CAN总线两端务必接120Ω终端电阻，否则通信不稳定。

## 五、核心模块说明

### 1. CAN网关模块(app_can_gw)
接收CAN总线报文，CRC8校验；完成报文解析；上报节点状态；处理CAN Bus‑Off故障，带最大重试次数的自愈恢复；将有效数据送入业务处理。
> 关键点：任务心跳上报放置主循环入口，每轮循环无条件执行，解决总线空闲场景看门狗误判卡死问题。

### 2. 故障管理器 fault_mgr
集中故障事件管理，故障事件队列 + 故障历史环形缓冲区；故障码转字符串；故障告警输出驱动LED、蜂鸣器；区分业务故障与整机死机。

### 3. 系统监控 app_sys_mon
FreeRTOS多任务心跳监控，监视各个业务任务运行状态；独立看门狗IWDG保护，仅监控调度器完全卡死；业务空闲（总线无报文）不会触发硬件复位，仅上报业务故障。

### 4. UART‑CLI维护终端 app_uart_cli
实现异步打印队列`App_ReportPrint`，替代裸调用`printf`，避免多任务串口竞争阻塞；提供串口命令交互，查看节点状态、读取故障记录、读写配置参数。

### 5. 参数存储模块
配置参数保存在片内Flash，支持掉电保存；可通过CLI命令修改参数。

### 6. F103采集节点
ADC采集电压、NTC温度；按键检测；组帧，CRC8校验，CAN2.0B发送上报采集数据。

## 六、通信协议简述
1. CAN：CAN2.0B标准帧，自定义应用层协议，每帧携带CRC8校验，保障数据可靠性；支持多节点组网。
2. UART‑CLI：串口交互，文本命令，返回OK/ERR，支持查询、配置、故障读取。

## 八、已知限制与注意事项
1. Flash参数写入有擦写寿命，业务中避免高频循环写参数。
2. CAN总线物理层必须配置120Ω终端电阻，否则会出现丢包、通信异常。
3. IWDG独立看门狗一旦启动，软件无法关闭；仅兜底RTOS调度器卡死，业务故障仅上报告警，不直接整机复位。
4. 异步打印队列满时消息会丢弃，不阻塞业务任务。
